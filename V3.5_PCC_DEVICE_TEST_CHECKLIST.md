# v3.5 P1 — PrivateCloudCompute — Device Test Checklist

**Covers:** commit `b80eb8a` on `claude/3-5-roadmap-f2ij61` (STLLanguageModel +
Auto-Fill + insights). **Ticket:** Asana `1218494005064476`.

## Why this list exists
Build, unit tests, and the simulator all pass — but **none of them exercise
real Private Cloud Compute**. Simulators have no Apple Intelligence / PCC, so
every automated check ran the on-device or no-model path. Everything below needs
a **real iPhone on iOS 27 with Apple Intelligence enabled**, because it's the
only place the PCC path actually runs.

## Setup
- [ ] Real iPhone, **iOS 27**, **Apple Intelligence enabled and eligible** (Settings › Apple Intelligence).
- [ ] Signed build of this branch installed (unsigned launch-crashes on CloudKit).
- [ ] **Pro** state (Auto-Fill is Pro-gated) — via sandbox or the FORCE_PRO path.
- [ ] A team with an active roster **and** several game logs (enough to matter for insights — see the 32k test below).
- [ ] **Network on** (PCC is a server model). You'll toggle it off for the fallback test.
- [ ] A way to read the `ai.model.usage` TelemetryDeck signal (dashboard, or a temporary console log at `STLLanguageModel.logUsage`) so you can see which `backend` actually served each call.

## A. PCC actually engages
- [ ] Run an Auto-Fill by voice/Shortcut or the ⚡ button, then check the `ai.model.usage` signal: **`backend = pcc`** for `feature = autofill_parse`. (If it's `on_device`, PCC isn't being selected — investigate `pccModel.isAvailable` on this device before trusting any of the "quality" results below.)
- [ ] Generate Game Log insights, confirm `ai.model.usage` fires with `feature = insights`, `backend = pcc`.
- [ ] Token counts look sane (input/cached/output/reasoning all present and non-absurd).

## B. Auto-Fill quality (the point of the 32k + reasoning)
- [ ] Run the **Bug 3 / Bug 6 prompts** recorded in the FillLineupIntent ticket. They parse correctly.
- [ ] A genuinely multi-clause prompt (e.g. "Caleb pitches the first two, keep the twins apart, nobody benched back-to-back, Mia at short when she's in") parses into the right constraints — the case the ~8k on-device window used to choke on.
- [ ] Spot-check the same prompts feel at least as good as the on-device baseline (no regressions in the simple cases).

## C. Guided generation over PCC (CONFIRM #3, live)
- [ ] For an Auto-Fill parse where PCC is the backend, confirm the **schema (constrained-decoding) path** is what ran, not the on-device retry. Two ways: the structured result resolves cleanly, and `backend` stayed `pcc` for that parse.
- [ ] If PCC does **not** declare `.guidedGeneration` on this device, confirm the parse **retries on-device** and still returns a correct structured result (never silent prose matching). You may need to eyeball a log to tell which branch ran.

## D. Insights context window (32k)
- [ ] With **many** game logs (more than the ~10-log `exceededContextWindowSize` trim threshold), generate insights and confirm the full-context insight comes back **without** hitting the trimmed-prompt path — that fallback should now be rare on PCC.
- [ ] Insight prose is coherent and uses the extra context (references more than the last handful of games).

## E. Graceful degradation / fallback (CONFIRM #6, live)
- [ ] Start an Auto-Fill / insights request, then **turn on Airplane Mode** (or otherwise kill network) to force a PCC failure. Confirm it **retries on-device** and completes — no error card, no hang — rather than failing the whole action.
- [ ] On a device/state where **Apple Intelligence is unavailable**: Auto-Fill's prompt field is hidden (or `.unsupported`), insights shows `.unsupported`, nothing crashes.

## F. Floor unchanged (iOS 26)
- [ ] On an **iOS 26** device: features work exactly as before, PCC never selected (`backend = on_device` everywhere), no new behavior.

## G. Gate + guardrail
- [ ] **Non-Pro**: Auto-Fill still gated (no new paywall, same gate as before).
- [ ] **Guardrail**: Fair Play rules and Pitch Eligibility answers are still the **structured** values — confirm no pitch-count / rest-day number is being phrased by the model. (This path shouldn't touch them at all; this is a regression guard.)
