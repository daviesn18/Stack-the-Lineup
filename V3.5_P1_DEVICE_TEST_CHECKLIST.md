# v3.5 P1 — Real-Device Test Checklist

Branch `claude/3-5-roadmap-f2ij61`. These are the checks that a simulator can't
cover (CloudKit sharing across two iCloud accounts, live StoreKit entitlements,
real Siri voice + interactive prompts, signing). Automated build/unit/UI tests
already pass — this is the human-on-a-device layer.

**Do #1 even if you skip everything else** — it's the only one that could
corrupt a real coach's shared roster.

Prereq: a **signed** build of this branch installed on a real device (unsigned
builds launch-crash on the CloudKit entitlements).

---

## 1. ⚠️ Shared-team archetype decode — data safety (highest priority)
Guards against a schema change breaking an **older** build's decode of a shared roster.

- [ ] **Setup:** Device A = this branch build, signed in as a Pro account.
      Device B = a *different* iCloud account running the **current App Store /
      TestFlight build** (the one without Hitting Archetype).
- [ ] A shares a team with B (or reuse an existing share) and B accepts.
- [ ] On A: open the shared team, set a Hitting Archetype on a player, let it sync.
- [ ] **PASS:** On B, the shared team's roster still loads fully — every player,
      no blank/missing rows, no crash. (B ignoring the archetype is fine; B
      failing to load the team is the bug.)
- [ ] **Reverse (nice-to-have):** a teammate already on the *new* build sees the
      archetype value come across correctly.

## 2. Signed launch + CloudKit sync
- [ ] Signed build installs and launches to the roster (no entitlement crash).
- [ ] An edit on one device propagates to another on the same account.

## 3. Pro-gate UX by voice (real Siri + StoreKit)
- [ ] **Non-Pro** account — *"Hey Siri, fill lineup"* → app comes **forward
      showing the paywall** (not a silent dead-end on some other tab).
- [ ] **Non-Pro** — *"How did the [team] do today?"* → Siri **speaks a Pro
      error**, app does **not** open.
- [ ] **Pro** account — *"fill lineup"* actually fills and routes to the
      Positions tab.

## 4. 🆕 Read-only-team fallback, live (the new 5a code)
The one interactive path the test harness can't drive (error 206) — only the
pure decision logic is unit-tested.

- [ ] **Setup:** roster has a view-only **shared** team **plus 2+ writable**
      teams; make the **shared (read-only) team active**.
- [ ] *"Hey Siri, fill lineup"* → **PASS:** Siri shows the **"Which team should
      I fill?"** prompt (not an error); picking one fills it.
- [ ] **Single-writable-team wrinkle:** read-only team active + **exactly one**
      other writable team → it auto-fills that one. Confirm Siri's spoken reply
      isn't confusing (it does **not** name the team it filled).
- [ ] **Decision:** should *explicitly naming* the read-only team still redirect,
